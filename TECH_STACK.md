# Технический стек LiftLab

Этот документ описывает только действующий production-контур. Исторические промежуточные решения не являются контрактом проекта.

## Архитектура

```text
App.tsx / ScenarioForm
  → simulation.worker.ts
  → scenarioRunner.ts
  → дискретно-событийное ядро src/engine
  → компактный BrowserSimulationResult
  → ResultsView / SavedScenariosView / сравнение
```

Расчёт выполняется в браузерном Web Worker, поэтому React-интерфейс остаётся отзывчивым. Ядро не импортирует React, не обращается к DOM и не зависит от скорости отрисовки. Backend для расчёта и публикации статической сборки не требуется.

## Основные модули

| Область | Файлы и назначение |
|---|---|
| Форма | `scenarioForm.ts`, `ScenarioForm.tsx` — defaults, преобразование и валидация |
| Запуск | `simulation.worker.ts`, `scenarioRunner.ts` — фоновый полный день |
| Ядро | `src/engine/` — события, диспетчер, маршруты, расписания и метрики |
| Результат | `browserResult.ts`, `ResultsView.tsx` — компактный контракт и визуализация |
| Ссылки | `scenarioLink.ts` — версия и `#settings=` |
| Сохранение | `savedScenarios.ts`, `SavedScenariosView.tsx` — до 20 записей в `localStorage` |
| Сравнение | `scenarioComparison.ts` — совместимость и дельты 2–3 вариантов |
| Методика | `MethodologyView.tsx` — пользовательское описание формул и правил |

## Действующие возможности ядра

- воспроизводимый seeded RNG и событийное время в десятых долях секунды;
- полный день: приход, персональные встречи, обед и уход;
- стратегии global FIFO, nearest и hybrid;
- общий этажный вызов, вместимость, попутный подбор и повторный вызов через 0,1 с;
- индивидуальные остановки и начальный этаж каждой кабины;
- подземный паркинг сотрудников и парковка кабин по расписанию;
- обязательные и добровольные лестничные участки;
- персональные ожидание, поездка и полное время, операционные метрики и гистограммы.

## Зависимости

| Инструмент | Версия проекта | Назначение |
|---|---:|---|
| Node.js | 26.7.0 | инструменты разработки |
| npm | 11.19.0 | единственный менеджер пакетов |
| TypeScript | 7.0.2 | типы и расчётное ядро |
| React / React DOM | 19.3.0 | интерфейс |
| Vite | 8.3.0 | dev-сервер и production-сборка |
| Vitest | 5.0.0 | модульные, интеграционные и сценарные тесты |

Точные разрешённые версии зафиксированы в `package-lock.json`. Новая зависимость добавляется только после проверки, что задачу нельзя достаточно просто решить текущим стеком или Web API.

## Команды

```bash
npm ci
npm run dev
npm test
npm run build
```

`npm run benchmark` — отдельный тяжёлый performance-прогон; он не входит в обычную быструю проверку.

Для браузерной проверки через Chrome DevTools Protocol сначала нужен Chrome с CDP на порту 9224, затем:

```bash
node scripts/browser-acceptance.mjs 9224
```

Скрипт проверяет навигацию и валидацию, но не заменяет ручной замер тяжёлых сценариев в Chrome и Яндекс Браузере.

## Что намеренно не используется

- серверный фреймворк и база данных — пока нет общего серверного хранилища;
- Redux/Zustand — локального состояния React достаточно;
- библиотека дат — время модели представлено числовыми метками;
- библиотека графиков — текущие диаграммы строятся средствами приложения;
- XLSX-библиотека — экспорт XLSX пока не является требованием.

## Публикация

`npm run build` создаёт статическую папку `dist`. Для общего доступа понадобится HTTPS-хостинг статических файлов; выбор площадки является отдельным следующим этапом.
